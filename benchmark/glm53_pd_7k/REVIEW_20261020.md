## 1. InputSP：通信字节增加，仍可能更快

定义 `S` 为一个 CP 分片的完整 BF16 activation 大小，只计每 rank
发送 payload，不把收发重复相加。固定 TP8/CP4/attention-TP2：

| 路径 | 每 rank 发送 payload |
|---|---:|
| 原 TP2 AR + CP4 AG | S + 3S = 4S |
| 候选 TP2 RS + TP8 AG + residual TP2 AG | 0.5S + 3.5S + 0.5S = 4.5S |

16K chunk、hidden6144 时，CP-local 4096 行，S=48 MiB；
原 192 MiB，候选 216 MiB，**每层该边界发送增加 24 MiB/rank**。
本地 residual clone 另计 HBM 流量。Norm 行数减半不等于
attention/MoE GEMM 减半，也不等于全模型通信量减少。

### 已有的服务内 profile

R5 按 CPU launch correlation 归属 step，而不是按异步 kernel 时间戳
硬切。baseline 有 4 个约 8.5K-fresh step；candidate 有 3 个同量级 step
和一个 **1-token 探针 step**。必须排除探针，不能对整份 trace 求比值。
以下为 rank0、大 step 的均值，单位 ms，均受 profiler 扰动：

| GPU 时间分类 | baseline n=4 | candidate n=3 |
|---|---:|---:|
| 所有 kernel 时间区间并集 | 1440.734 | 1364.046 |
| 仅通信活跃的时间区间 | 813.190 | 737.978 |
| 仅计算活跃的时间区间 | 620.348 | 620.471 |
| 通信与计算重叠区间 | 7.196 | 5.597 |

按 process group 和 6144 列 shape 汇总的 NCCL kernel 时长：

| 操作/组 | baseline | candidate |
|---|---:|---:|
| attention-TP AR | 77.224 | 4.351 |
| attention-TP RS | 0 | 42.431 |
| CP AG | 426.115 | 3.490 |
| TP8 AG | 0 | 350.807 |
| attention-TP AG | 28.864 | 57.308 |

最后一行包含原有 MoE 出口 AG 和新增 residual AG；同 shape 的汇总不能
把一半精确指定给 residual。表中可能含等待和跨流重叠，**不能把各行差值
加起来当端到端收益**，也不能把 NCCL kernel 时间当纯链路数据时间。

可支持的解释：此 trace 的净变化主要出现在通信/同步路径，未看到计算独占
时间下降；collective 分组和调用形式改变后，即使总 payload 更多也可能更快。
但还不能确定是算法、拓扑、排队还是有效带宽贡献最大。Norm、clone 的细分
未单独恢复，不能把收益归因成“Norm 快了一半”。合成完整边界微测
（包括恢复 residual）在 CP-local4096 行为 8.112→6.440ms，作为佐证，
不是整机收益。

### 不带 profiler 的配对结果

R2 为 BAAB、每臂 128 请求、到达率0.85/s，共512条成功。
中段首有效增量速率 baseline 0.687119/0.688498，candidate
0.724268/0.724790 req/s，两臂均值比为 **+5.339%**。
这包含交接和首 token，不是纯 P 算子 TPS；双方都积队列，不能称稳态容量。

R3 为 ABBA、每臂160请求、0.70/s：baseline TTFT P50约6.52s且
队列增长，candidate约2.82s且短窗接近平稳。单臂约4分钟，不是长稳SLA。
历史实际层比对覆盖8rank、每rank600次调用，hidden/residual逐位一致；
这不是全题集精度保证。

**修改边界：**不直接删 residual AG，否则下游拿不到既有 CP-local 完整
residual。跨层 SP 必须同时改 MoE 出口、下一层入口、padding、aux/MTP
捕获和末层布局，再核算完整一层的通信量。不能把 AG 挪到下一层就算节省。
融合方案必须先确认 SM120/NVFP4 backend 的可用实现，不套用 B200/BF16
报告的收益。本次不改变正在跑的 GPQA 的算子或布局。

## 2. LayerSplit：先前开启正确，后来关闭是另一项取舍

LayerSplit 是社区原有能力（`8e54517f02` / #29421），我们之前启用并适配了
部署组合，并非本 PR 新发明。每个 CP owner 持久保留自己负责层的全部 token
KV/index，非 owner 读层时使用广播 scratch。

2026-10-05 的历史记录：旧 PCP4 池约217K，在当时C16负载发生缓存
反复驱逐；LayerSplit 部署池可到约806K，16K batch/mem0.90时约540K。
这些是历史部署记录，不是本次重新做的严格等预算 A/B，但明确了当时
启用它的容量目的。记录也定位到逐层整池 KV/index 广播包含未使用页，
因此池子越大，广播代价可能越大。

R27/R28 则固定池 **110464 tokens**、memory参数0.88：

| | LayerSplit | 完整 KV |
|---|---:|---:|
| 实际逻辑 pool tokens | 110464 | 110464 |
| 记录的 KV 分配 GiB/rank | 1.54–1.62 | 6.33 |
| P 历史 KV/index 读取 | owner 广播 | 完整本地副本 |
| PD 来源 | 各 owner 负责层 | CP0 对应两张 attention-TP 卡 |

因为显式 token cap 限住池子，额外约4.7GiB来自未使用的显存余量；
相同 `mem_fraction_static` **不等于**相同实际 KV 字节消耗。没有测出相同
实际显存预算下的 capacity ratio，更不能把110464乘8变成独立 token 数。
如果同预算、每 P 的独立长前缀更多，关闭 LayerSplit 完全可能更差。

### +10.9% 的准确含义

对照每臂96请求，固定1 req/s，输出1，窗口20–80s。真实输入
85151–85285 token，命中约89.90–90.04%，**并非后来严格的81920/73728
资格负载**。两臂输入相同：

| | LayerSplit（R27b） | full-KV＋bounded-pack（R28） |
|---|---:|---:|
| 整臂完成/错误 | 96/0 | 96/0 |
| 窗口完成数/到达数 | 46/60 | 51/60 |
| HTTP 完成速率 req/s | 0.7667 | 0.8500 |
| fresh input TPS | 6535.3 | 7245.3 |
| backlog 始→末 | 7→21 | 6→15 |

51/46−1=**10.87%**，但同时变化了布局和超大 transfer 处理。只能称该组合
在此短窗改善 HTTP 完成速率；不是关闭 LayerSplit 的独立稳态增益。
另一个所谓 repeat-comparison 文件只含一个完成 arm，不计成独立性能复测。
首 token top1对照一致，但logprob并不完全相同，不作为全模型数值等价证明。

**保留策略：**LayerSplit 做容量优先基线；full-KV/CP0-only 只作为已验证
小热工作集配置。CP0为两张attention-TP卡，不能把它说成单卡，或把每活跃源卡
更多层数据推导成总RDMA字节4倍。每P多个独立长前缀、慢D/网络、CP0发送热点
以及等预算拐点仍需要单独验收；本轮没有这些新结果。

## 3. 有界打包：修复已遇到的超时，但单项性能尚未定量

R27 完整KV第一次冷请求完成，随后 P 热、D 冷请求约32s传输超时。
已记录 payload 1,959,939,072B，大于原 buffer 838,336,512B，
转入原来的碎片回退。R28用同一注册buffer同步分块复用后，
16条长输入冷/热自然结束用例通过；8rank共35568次实际SparseMLA
KV字节比对无差异，随后96条短轮完成。**这支持该失败场景的恢复，
不构成这项改动独立 +X% 的性能证据。**

依然缺少：R65/R66实际触发次数/比例和拆块数、D命中与实传字节、
逐来源 pack/同步/RDMA 时间、描述符数、P50/P99、每源GPU注册buffer
总量和峰值临时量。单buffer大小不等于每GPU总常驻量；要乘实际worker/
queue拥有者数量，不能从未知数量推算。

不改变目前buffer预算、不新增双buffer。未来固定其他变量测试：
容量内、刚超容量、数倍容量 × 连续/碎片页 × 冷D/热D；一次只切
`SGLANG_RESEARCH_DCP_BOUNDED_PACK`。失败仍计入结果；如果旧路径超时，
报告错误率和有界观测，不能把timeout当成功延迟来算加速比。

## 4. 社区候选与下一步

评论引用的 LayerNorm SP、模型内SP和KV sharding各自有模型、硬件、MTP、
PD/L3兼容边界；名称相同不视为当前组合等效。本次没有重新宣称这些开放PR
已合并，也没有打开它们。优先顺序：

1. 不变代码补齐InputSP完整边界callsite profile、Norm/clone及通信有效时间；
   在固定shape/负载做暖态多次配对，区分等待与带宽。
2. 单buffer bounded-pack单变量对照及R65/R66负载触发率，避免把基础修复
   当算力红利。
3. LayerSplit/full-KV的**等显存预算**与每P独立前缀数量扫描；同时观察
   locked/evictable/free tokens与CP0发送排队。
4. 证据支持后才实现持续residual分片；来源轮换、page-sharded KV则分别立项。
   page sharding会重新引入prefix聚合/scratch，不预先认定更快，也不只删guard。

以上均未在本轮启动。GPQA继续使用原固定版本，不与性能实验重叠。
